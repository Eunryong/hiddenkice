# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Current state

This repository is **pre-implementation**. No application code, `package.json`, or framework config exists yet — only design docs (`docs/`), Supabase seed CSVs, and image assets. The Next.js app described below still needs to be scaffolded. When implementing, follow the architecture decisions already locked in `README.md` and `docs/DESIGN_NOTES.md` rather than re-deciding them.

The project is a single-page textbook catalog ("교재 목록 페이지") for Hidden Kice: Header, a main promotional banner, search/category filters, a textbook grid, and Footer. Textbook and banner data are fetched **client-side (CSR)** from Supabase. Most docs and seed data are in Korean.

## Target stack

Next.js (App Router) · TypeScript · Tailwind CSS · Supabase (CSR queries) · Vercel (auto-deploy from `main`).

## Planned architecture

Feature-centric layout under `src/` (full tree in `docs/DESIGN_NOTES.md` §6). The key boundaries:

- `app/` — `layout.tsx` + `page.tsx`. The page component only **composes** the screen; it does not fetch data directly.
- `components/layout/` (Header, Footer) and `components/ui/` — reusable, domain-agnostic UI shared across pages.
- `features/textbooks/` — all textbook/banner code is colocated here: `api/`, `components/`, `hooks/`, `types/`, `utils/`.
- `lib/supabase/client.ts` — the Supabase client.

Data flow: pages get state only through hooks (`useTextbooks`, `useTextbookBanners`), which call the `api/` layer. **Never write Supabase queries inline in components.** This keeps textbook and banner fetch conditions independently extensible (search, category, sort added later in one place).

## Design decisions that aren't obvious from code

These are deliberate choices documented in `docs/DESIGN_NOTES.md` — honor them:

- **Domain is `textbooks`, not `products`.** The core entity is study textbooks, not generic commerce items.
- **`TextbookMainBanner` lives in `features/textbooks/components/`, not `components/layout/`** — it's a domain promo banner, not a global element. Banners are treated as **operational data fetched from Supabase**, not hardcoded, because operators may swap/reorder them (the Figma `1/5` page indicator implies multiple rotating banners).
- **`price` is read from the DB, never computed client-side.** `original_price` + `discount_rate` are display-only. Real selling price can diverge from the naive calc due to coupons/events/manual adjustments, so the stored `price` is authoritative.
- **Figma's `1440px` fixed widths / absolute positions are references, not literals.** Reconstruct with Flex/Grid; the textbook list must be a responsive grid, not fixed coordinates.
- **Purchase state is intentionally NOT a column on `textbooks`.** It's per-user state, modeled via a separate `user_textbook_entitlements` table (entitlements, not order history) to handle refunds/admin grants/pass expiry. Not in current scope, but don't add `is_purchased` to `textbooks`.

## Supabase data

Two tables, seeded from `docs/supabase/*.csv` (field docs in `docs/supabase/DATA_FIELDS.md`, full DDL in `README.md`):

- `textbooks` — `id, title, textbook_type, image_url, original_price, discount_rate, price, display_order, is_active, created_at`
- `banners` — `id, title, image_url, link_url, display_order, is_active, created_at`

Conventions: numeric `bigint` PKs named `id` (not `index`); display order is the separate `display_order`. Tables use `generated by default as identity` so CSV imports can supply explicit `id` values. `textbook_type` filter values are `단품` (single) and `패스` (pass/bundle).

Images: DB stores **only the URL/path** (e.g. `image/textbooks/textbook1.webp`), never the file. Use WebP and Next.js `<Image>` with fixed dimensions/aspect-ratio to avoid layout shift. Assets currently live in `image/`; production may move to Supabase Storage.

## Environment

Supabase credentials are env vars (never committed); the same must be set in Vercel:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

## Scope discipline

In-scope: render the textbook list + main banner via CSR from Supabase. Cart, orders, entitlements, notifications, and admin banner management are **explicitly out of scope** — but the data and folder structure are designed so they can be added later without rework. Also account for loading / error / empty states for every CSR fetch.
